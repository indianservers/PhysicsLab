# 2D Teaching & Learning Studio Rollout — Lessons 011–080

## Standard applied to every lesson

Each lesson will use the same production loop proven on 001–010: verify the physics model and edge cases; define one visible learning objective; build a direct-manipulation 2D stage; synchronize controls, animation, measurements, equations and graphs from one state model; add prediction before play; add a measurable mini-mission with feedback; provide play, pause, fixed step, reset, speed and reduced-motion controls; support pointer, touch and keyboard; then validate desktop, tablet, mobile, interaction state, mission completion, build and physics tests. There will be no click sounds or game sounds.

PNG assets are layered apparatus or scenery only. Quantities that teach physics—vectors, rays, particles, trajectories, fields, graph traces, meter needles, fluid levels, charge flow and collision states—remain code-rendered and live.

## Optional 3D only

Most lessons need no GLB. Keep 3D as an optional inspection mode only for spatial relationships that are materially clearer than 2D. If custom models are commissioned, the useful shortlist is:

1. `017-transformer-cutaway.glb` — separable core, primary, secondary and flux path.
2. `043-rotational-inertia-rig.glb` — disk/rod with draggable radial masses.
3. `057-optical-instruments-cutaway.glb` — separable microscope and telescope tubes/lenses.
4. `064-coupled-oscillator-rig.glb` — two masses, springs, anchors and selectable camera markers.

All four must use named parts, compressed textures, Draco or Meshopt geometry compression, one neutral animation-free rest pose and a 2D fallback. No other GLB is required for 011–080 at this stage.

## Delivery order and quality gates

Work remains strictly sequential inside each batch. A lesson advances only after its physics tests, keyboard/touch interaction, prediction, mission, desktop/tablet/mobile screenshots and discrepancy record pass. After each ten-lesson batch: run the complete physics suite, production build, route smoke test and asset audit; then commit the batch on `main` only when the user requests the commit/push.
